      Users & Roles

      Local accounts for this app. Roles: admin (manages users and roles), buyer (works purchase requests and POs), viewer (read-only).

      Leave the initial password blank to have that user set their own password at first login, the same way the default admin account works.

      Demo

      Simulates 100 buyers repeatedly asking the copilot's common questions ("My priority", "Compare suppliers", "Explain oversupply", "PO readiness") across this app's seeded purchase requests. Every request goes through the real copilot → Couchbase Agent Operations Manager (AOM) path — nothing here is faked. A closed-loop controller deliberately mixes in a calculated share of genuinely fresh (never-before-asked) questions alongside repeats, so the trailing one-minute hit rate you'll see in Couchbase Agent Operations Manager's own Cache Dashboard drifts in a slow, natural-looking wave between about 82% and 96% for as long as the demo keeps running, rather than climbing toward a suspiciously perfect 100%. Expect a lower rate for the first 20-30 seconds while the question pool is warming up. No purchase requests, POs, or buyer-action records are created — stopping the demo leaves nothing behind to clean up.

      COUCHBASE_AOM_API_KEY isn't set, so this will simulate the copilot's traffic pattern but never actually reach AOM — the fallback rule-based text will always answer instead. Configure AOM in this app's .env to see real cache hits.

      Agent Simulation

      Runs two role-played Couchbase Agent Operations Manager (AOM) identities against this app's real copilot and MCP tool paths, once a minute. Every tick, a support_agent "customer support call" asks the copilot to explain an oversupply alert or confirm PO readiness on a random purchase request and checks Zendesk for related open tickets, authenticating to AOM as its support_agent identity throughout. Every few minutes, an admin turn also runs AOM's bundled Web Search and Internal Docs Search tools and creates a Jira issue via AOM's Jira MCP server. All of that hits AOM's own bundled sample MCP servers, which return mocked data and make no real external request or write of their own — including the internal docs search, which AOM quarantines at ingest as one of its own MCP-hijacking fixtures, so it's expected to come back empty every time, and the web search, whose mocked response is the other fixture — watch it flag a live finding on AOM's own Threat Detection page the first time it runs. No purchase requests, POs, or buyer-action records are created here either — stopping this leaves nothing behind to clean up.

      No Couchbase Agent Operations Manager API key is configured for the admin role, so this will run but never actually reach AOM — no LLM narration, tool calls, or Jira issues will happen. Configure AOM in this app's .env to see real activity.
